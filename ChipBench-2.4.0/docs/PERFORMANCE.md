# 性能说明（ChipBench 1.1）

## 方法
`tests/t_perf.py`：在无头 Chromium（Linux 容器，软件渲染、无 GPU）里生成 20,813 行、约 449 K 字符的中英混合文档，测量打开、打字、滚动、索引、搜索、日志。
**这不是 Windows 真机数据**：绝对值请以你本机为准（通常更快），这里主要用于发现退化。`scripts/check_perf.py` 把结果与预算比较，CI 中超出预算会失败。

## 1.1 与 1.0 对比（同一容器、机器空闲时各测一次；1.1 两次干净运行）
| 指标 | 1.0 | 1.1 第 1 次 | 1.1 第 2 次 |
|---|---:|---:|---:|
| 启动（DOMContentLoaded） | 995 ms | 883 ms | 1000 ms |
| 打开 2 万行文档（实时预览） | 1490 ms | 1700 ms | 1227 ms |
| 实时预览打字：中位数 / 最慢 5% | 24.9 / 79.7 ms | 24.8 / 73.5 ms | 24.8 / 71.6 ms |
| 源码模式打字：最慢 5% | 56.5 ms | 27.5 ms | 36.2 ms |
| 源码模式长任务（>50 ms） | 2 | 0 | 0 |
| 分屏预览更新（中位数） | 285 ms | 206 ms | 254 ms |
| 阅读模式首屏 | 553 ms | 523 ms | 578 ms |
| 常见词搜索 | 29 ms | 14.5 ms | 16.6 ms |
| 打开大文档后内存（GC 后） | — | — | 38.3 MB |

说明：
- 1.0 的“打开大文档后 JS 堆 47 MB”是**没有先回收垃圾**的读数；1.1 起 `t_perf.py` 先 GC 再读（另记录未 GC 的 `heap_big_open_raw_mb`）。用同一篇文档在 GC 后对比，1.0 和 1.1 都是 12.4 MB，1.1 没有增加常驻内存。
- 实时预览打字的“最慢 5%”只改善约 10%，仍高于 50 ms 目标；这部分取决于 CodeMirror 装饰计算，彻底解决要做“实时预览完全虚拟化”（列入 1.2）。
- 包体积：中文字体从 3.5 MB 降到约 2 MB（常用字子集），生僻字回退到系统的 Microsoft YaHei UI。
- 搜索索引持久化后，重启时直接恢复索引；`t_v11.py` 验证了恢复后可立即搜索，Windows 上的实际耗时需要你本机测。

## 诚实的说明
- 实时预览里最慢 5% 的按键延迟在不同次运行间波动较大（本地多次运行约 39–63 ms）：软件渲染环境下偶尔超过 50 ms 的目标。真机请用 `t_perf.py` 复测。
- 没有测量：Windows 上的启动时间、安装后的总内存、1,000 页 PDF、1 GB 日志（只测了 30 万行）。这些需要在真机上验证。
- 已做的优化：源码模式输入的刷新间隔随文档大小自适应；大纲取自语法树；预览按组懒渲染；PDF 只渲染可见页；日志由 Rust 建稀疏索引、前端虚拟滚动；全文索引增量更新；PDF 文字提取缓存到磁盘。
- 分屏预览的 Markdown 渲染已放入 Web Worker。
- 未做：文档内部按行存储、实时预览完全虚拟化（见 FEATURES.md）。
