## 2.3.0 · 2026-10-30 —— 行为规则与推演引擎（检查点：引擎 + MCP，界面稍后）

**是什么，不是什么**：场景只记录“写了哪些寄存器值”。2.3 让你把**手册里写明的行为**写成规则，再把场景套上去，看规则推出什么（例如“状态 & 使能 → 中断线”“每次推入计数 +1，满了置位”）。引擎**不认识任何芯片**，只执行写进模型的规则；每个结果都标“推导”，并列出它依赖的规则及其依据等级（手册确认 / 实测 / 推导 / 示意 / 待核对），用到了没有手册依据的规则会明确提醒“视为假设”。没有规则时它什么也不推导，只重放场景里写的值，并且这样告诉你。

**规则**（模型新增 `rules`；新增 3 个原子操作 `add_rule / update_rule / remove_rule`，操作总数 21 → 24）
- 电平规则（level）：条件成立时执行“满足时”，不成立时执行“否则”，用于“状态跟着条件走”（中断线 = 状态 & 使能）。动作不能读自己要写的目标（那是计数行为，会被拒绝并提示改成边沿规则）。
- 边沿规则（edge）：条件由假变真的那一刻执行一次，用于计数、事件；条件一直为真时不重复触发；上电时已经为真视为“已激活”，不触发。`emit "文字" @节点` 只能用在边沿规则里。
- 动作只有两种：`set 名字 = 表达式` / `set 寄存器.位域 = 表达式`（位域赋值按位宽截断，不影响其它位）、`emit "文字" @节点`。
- 引用检查：条件和动作里引用的寄存器 / 位域 / 节点必须存在；变量被读取却从未被赋值会给出“拼写错误？”提醒。
- 一致性：重命名节点会同步 `emit @节点`；删除节点只去掉高亮、保留事件文字；**删除被规则引用的寄存器会被拒绝**并指出是哪些规则（公式不会被自动改写）。

**表达式语言**（`ip-expr.js`，手写解析器，**没有 eval**）：整数（十进制 / 0x / 0b / 下划线）、`名字`、`寄存器.位域`、括号、`! ~ -`、`* / %`、`+ -`、`<< >>`、比较、`& ^ |`、`&& ||`（C 语言优先级）。没有函数调用、字符串、赋值、属性访问；整数任意精度；`/` `%` 向零取整；除数为 0、移位个数超过 4096、表达式超过 400 字符或嵌套超过 48 层都是明确的错误，不会卡死。规则来自人、AI 或共享文件，所以它不可能执行代码。

**推演引擎**（`ip-sim.js`）：状态 = 寄存器值（起始为复位值或 0）+ 变量（起始为 0）。每一步先套用场景写入，再让规则“收敛”（逐轮按模型顺序执行，直到一轮没有变化；最多 32 轮，不收敛会明确报告而不是死循环）。数值上限 1024 位（两条规则互相平方不会吃光内存）。每个变化记录“是被哪条规则（或写入）改的”，精确到位域：只有真正翻转了该位域的原因才被归因。

**MCP（工具 60 → 61）**：新增 `ip_simulate`（只读；逐步显示变化 / 起作用的规则 / 事件 / 警告；`step=`、`format=json`）；`ip_read` 列出规则；`ip_list` 显示规则数；`ip_edit` 的说明里写明规则语法，并要求 AI **只在手册明确写了这个行为时才写规则、并给出页码；推测请标“推导 / 待核对”，宁可缺规则也不要编造硬件行为**。规则和其它修改一样默认是“提案”。

**两套实现逐项一致**：表达式 150 个输入（含恶意、畸形、Unicode、超长）、动作 35 个、51 个规则操作场景（包含拒绝时的错误码和文字）、23 个完整推演（含振荡、失控增长、除零、截断、事件、未核实规则）。变异检验：故意把 Python 的收敛上限改成 31、让边沿规则在上电时触发、允许删除被引用的寄存器，三种改动都被测试抓出。过程中还抓出一个真实分歧：JS 把 BOM 当空白而 Python 不，现在两边都只认 ASCII 空白（规则里的不可见字符是错误，不会被悄悄接受）。

**测试**：`ip-expr.test.js` 55 · `ip-sim.test.js` 39 · `ip-model.test.js` 101 → 125 · `mcp/test_ip23.py` 一致性 · `mcp/test_mcp18.py` 增加 14 项（含“没有规则时推演不推导任何东西”“未核实规则被标为假设”）。

## 2.2.3 · 2026-10-30 —— IP Studio：手动摆放 · 框选 / 多选 · 小地图（检查点）

**手动摆放**
- 拖动节点或分组 = **移动**它（位置存成偏移量，写进 `.layout.json`，不动模型文件）。移动分组 = 里面的成员一起走；成员再单独移动，偏移叠加。位置变化不会重新跑自动布局（ELK 命中缓存）。
- 分组会随成员变大：把成员拖到分组外并选“留在分组里”，分组框自动扩到能装下它；不会比 ELK 排出的框更小。
- 连线跟着走：两端都随容器一起移动的连线保留 ELK 的走线；只有一端移动的，重新走一条 3 段的直角线（从面对的那一侧出入）。拖到页面左上角之外时整页平移，节点不会被切掉。
- 放到**另一个节点上**仍是“连线 / 移入”（和 2.0 一样）；把分组里的成员拖到分组外的空白处会问：留在分组里（分组变大），还是移出分组（变成顶层节点）。轻微抖动仍算点击。
- 工具栏出现“重置位置”（清除全部）；选中已摆放的节点时详情页有“恢复自动位置”。
- 几何是纯函数（`app/js/ip-layout.js`），28 项 Node 单元测试：偏移叠加、分组生长（自下而上）、整页平移、连线是否保留走线、新走线的方向。

**框选与多选**
- 在空白处拖一个矩形 = 框选；Shift / Ctrl + 点击增减；Esc 取消。选中的节点有虚线描边。
- 多选后右侧显示“已选 N 个”：放进新分组…（一步撤销）、删除所选…（先说明连带多少节点和连线，一步撤销）、复制 id 列表、恢复自动位置。拖动其中一个 = 一起移动。
- 录制场景步骤时，矩形把框到的节点加入这一步（不产生多选）。

**小地图**
- 只在“节点 ≥ 25 且图需要滚动”时出现：整张图缩略 + 你正在看的那一块；点击或拖动来跳转，随滚动、检查器开关、编辑更新。拖动时才临时挂 document 监听，松开即摘除，关闭标签后无残留。

**测试**：`ip-layout.test.js`（28）· `t_place22.py`（40：移动 / 分组 / 成员出组 / 连线跟随 / 重开恢复 / 重置 / 多选 / 框选 / 成组 / 删除 / 场景录制）· `t_mini22.py`（16）。

**测试中发现并修好的真问题**：拖到分组外弹出的菜单在窗口底部之外（我把位置对象同时当“锚点”和“位置”两个参数传给了 `SL.menu`，导致 `left / top` 为 NaN，样式被浏览器丢弃）。

## 2.2.0 · 2026-10-30 —— 性能专项：大型 IP 模型（进行中的检查点）

**为什么**：从没拿大模型测过。用生成器造了 300 / 1000 / 3000 个节点的 `.cbip`（含分组、寄存器、3 个场景）实测，发现 300 个节点就已经难用：点一下节点 2.2 秒、切一步场景 1.6 秒、打开 4.5 秒；1000 个节点布局超时。

**根因（用对照实验定位，不是猜）**
- 约 90 % 的卡顿**不是 JavaScript**：每个节点的入场 / 选中 / 悬停动画、每条边的透明度过渡都在改 SVG 子元素，而浏览器不会把 SVG 子元素单独合成——每一帧都要重绘整张 3500 个元素的 SVG。关掉过渡和动画，首次点击从 2482 ms 降到 46 ms。
- 淡化“其余部分”用的是逐元素 `opacity`，每个元素都要建一个离屏图层（1000 个节点切一步场景 4.8 秒）。
- ELK 布局：300 个节点 1–2 秒、1000 个节点超过 20 秒硬超时；而且 CPU 连到几百个外设的“星形”被排成 4121 × 19652 的细长条。
- 折叠后的“概览”仍带着全部平行连线（17 个块、396 条线）。
- 第一次布局在新 worker 里要 ~0.9 秒（引擎尚未优化），与布局规模无关。
- 每次重绘校验 4 遍；`toIpblock` / `ref` 等按连线线性扫描（O(边 × 块)）。

**改动**
- **大模型默认打开概览**：块数 > 120 且有 ≥ 2 个顶层分组时，每个顶层分组折叠成一个块；平行连线合并成一条“×N”。双击分组只展开它；“展开全部…”会先确认并说明很慢。概览是**推导出来的，不写盘**；你自己折叠 / 展开之后才把选择写入布局旁路文件（`view.collapse = manual`），再次打开按你的来。聚焦子图时不用概览。
- **大图（> 80 个块）关闭逐节点动效**（入场、选中弹跳、悬停放大、透明度过渡、流动虚线、数据点）；静态状态（高亮、选中描边）照常显示。
- **高亮改用“面纱”**：场景步骤和搜索在大图里 = 一块半透明面纱 + 只克隆被点亮的节点 / 边放在上面；代价跟被点亮的数量有关，而不是跟图的大小有关。悬停 / 选中只加粗相连的边，不再淡化其它边。
- **布局参数按规模调**：≤ 60 块不变；61–150 `thoroughness 4`；151–400 `2` + GREEDY 断环；> 400 `1` + GREEDY + LONGEST_PATH。超时从固定 20 秒改为 20 秒 + 每块 90 毫秒（最多 180 秒）；布局期间显示“正在计算布局（N 个模块，M 条连线）…”。
- **布局失败有出路**：写明原因 / 影响 / 下一步，带“折叠成概览”和“重试”按钮。
- **空闲预热**：启动后约 3.5 秒空闲时启动 ELK worker 并跑一次小布局，第一次打开 .cbip 省约 1 秒。
- **编辑不重建没变的图**：改参数 / 备注这类不影响画面的编辑，不再重建上千个 SVG 元素；改依据等级（会改变颜色和页码标签）仍会重建。
- **数据层**：`toIpblock` 改成按索引（3000 节点 110 ms → 21 ms；折叠 259 → 9 ms）；`descendants`、节点查找、搜索可见性判断改成 Map / Set；`validate` 每个模型版本只算一次。

## 2.1.1 · 2026-10-30 —— 审查修复收尾：状态、生命周期、窄窗口（临时版本，待统一测试）
