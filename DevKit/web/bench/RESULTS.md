# MDView 1.0 性能测试结果

环境：Linux 容器内的无头 Chromium（软件渲染、无 GPU，速度明显慢于普通 Windows 电脑上的 Edge / WebView2，且波动较大）。请主要看**相对差距**。
测试文档：`gen_doc.py` 生成的 20,001 行、约 130 万字符的中英混合文档（标题、段落、列表、代码块、表格、引用、行内公式）。
对照组 `textarea`：用 `window.__MDV_NOCM` 关闭 CodeMirror，退回浏览器原生文本框——这是上一版（v3 覆盖层着色）源码模式性能的上限。

| 指标（2 万行） | CodeMirror 6 内核 | 原生文本框（对照） |
|---|---:|---:|
| 切换到源码模式 | 390 ms | 1,352 ms |
| 源码模式打字延迟 p50 | **39 ms** | 112 ms |
| 源码模式打字延迟 p95 | 249 ms | 413 ms |
| 源码模式跳到文末 | 14 ms | 94 ms |
| 实时预览块内打字 p50 / p95 | 17.8 / 106 ms | 6.5 / 13.8 ms |
| 打开文档（解析 + 渲染） | 614 ms | 540 ms |
| 修改一段后提交渲染 | 75 ms | 23 ms |

说明：
- 实时预览模式下，每次单击段落会创建一个小型 CodeMirror 编辑器，比原生文本框稍重，但延迟仍在一帧左右（< 20 ms p50）。
- 本版修复了一处大文档性能问题：实时预览的分块从“每块一个 content-visibility 容器”改为“每 40 块一组”，2 万行文档块内打字延迟从 ~360 ms 降到 ~18 ms；大纲高亮由逐项查询改为二分查找。
- 字数统计改为单次扫描，超大文档最多每 2.5 秒统计一次。

复现：
```
python bench/gen_doc.py 20000 > bench/big20k.md
python bench/bench.py cm          # 或 textarea；第二个参数可指定行数
```
